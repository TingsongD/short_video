# F07 — Submission recovery and retry policy

**Module / owner / source revision / completion date:** F07 · Devin · `feat/factory` post-F06 · 2026-09-16

**Scope implemented:** `Executor` — the shared effect-safety protocol for every remote adapter. `prepare()` writes intent + attempt + outbox in one transaction before any network call (auto-creating the parent job row for FK integrity); request hash is the wire-canonical hash the provider records so reconcile-by-hash actually finds the remote op; `submit()` marks `dispatching` → on receipt saves `remote_id` immediately → `accepted`; failure classes via `retry.classify` (`pre_acceptance`/`ambiguous`/`terminal`/`retryable_read`/`retryable_transfer`/`auth`); `poll()` maps remote truth incl. HTTP-200-with-error → terminal `failed`; `download()` retries transfer only; `reconcile()` by remote_id then request_hash; `recover()` restart scan returning reconciled/unknown/terminal; `request_cancel` (ack) vs terminal `cancelled`; `fallback_allowed` suppresses competing paid work while the original is unresolved; `resolve_unknown` requires evidence and only produces terminal outcomes. `FakeProvider` gained `cancel` (ack → cancel_requested → terminal on poll) so the protocol is exercised for real.
