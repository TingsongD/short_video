# F10 — Outlier discovery and baseline evidence

**Module / owner / source revision / completion date:** F10 · Devin · `feat/factory` post-F09 · 2026-09-17

**Scope implemented:** research scans → ranked, explainable candidates → seed export. `build_cohort` constructs the preceding comparable-video set (excludes seed, post-seed publications, mixed formats, cross-platform; bounds at 50, flags <20 as `small_sample`, >30-day spans as `mixed_periods`; every exclusion carries its reason). `evaluate` computes `follower_multiple` (strict `views > followers × 2`) and `baseline_multiple` (`views >= cohort_median × threshold`, inclusive at 5.0) as independent metrics — null denominators yield null, never infinity or fake zero; `provider_score` is stored separately, never relabeled. Selection modes `follower|baseline|either|both` are explicit and persisted. `DiscoveryService.scan` preflights planned pages, rides the F07 executor for every paid call, caches each (query,page) in a durable `discovery_cache` table (migration 7), records `partial` coverage with the exact received/planned split when credits exhaust mid-pagination, and exports only *selected* candidates to the seed registry — selection never authorizes generation. Every run persists an immutable `DiscoveryRun` record with plan, coverage, per-candidate cohorts (included/excluded ids + reasons + mean/median + flags), and verdicts — an engineer can recompute every ratio.

**Legacy path extension (per spec "extend the active path"):** `viral_records.normalize` now honors `selection_mode`, `baseline_threshold` and `cohort_median_views` from plan criteria — populating the real `channel_avg`/`multiplier`/`baseline_available` fields the frozen schema already defined — and `viral_scan.prepare`/`load_plan` persist+validate them. Default stays follower-only; all 69 legacy radar tests still pass.
