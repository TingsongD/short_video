## Design decisions

- **Idempotent `start`.** Before spawning, `ServiceManager.start`
  compares the registered `service-<name>` record against the live
  process table with F26 `same_process` identity (pid + birth +
  command). A live match returns `already_running` — no duplicate
  `records` insert, no second listener. A *dead* record is replaced
  by the new spawn; a *live but different* identity is a conflict,
  not silent replacement.
- **Ports are scanned, never cleared.** If the requested port is held
  by a pid the factory doesn't own, `start` walks `--alt` candidates
  or raises `port_occupied`. Nothing is killed to free a port
  (verified in F30-M02: foreign pid untouched).
- **Drain vs stop are distinct.** `drain` marks `draining` — accepted
  work and reservations survive; `stop` is a deliberate per-service
  termination through the F26 resource registry (TERM → KILL only for
  verified owned survivors).
- **Backups carry the money.** `manifest.json` includes the cost
  ledger copies, unresolved effect intents and budget/reservation
  state — restoring without them would fake spend headroom. Git is
  not the backup for gitignored financial state.
- **Restore ≠ activate.** A restored DB may reference remote effects
  the new workspace can't see. `activation_gate` reports
  `pending_effects` and keeps `dispatch_enabled` false until
  reconciliation succeeds and an operator explicitly activates —
  checked in F30-M04.
- **Credential separation.** `resolve_config` returns values +
  sources for safe keys and only set/unset *refs* for secrets;
  nothing secret can leak into the dashboard build or API responses.

## Open risks / manual verification

- The real `start` launches via `subprocess.Popen`; restart-policy
  tuning (backoff, max restarts) is conservative and untested against
  long-lived crash loops — watch a real overnight run.
- `gdrive`/Canvas/Vertex native logins still need human re-auth after
  a restore onto a new machine — `doctor` reports readiness but
  cannot perform the OAuth flows.
- Port alternatives are configured per-start; if the requested *and*
  all alternates are foreign-held, `start` fails clearly but does not
  auto-pick a random port — deliberate, to keep the dashboard URL
  stable.
