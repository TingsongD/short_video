## Confirmed factory defects

The [diagnostic probes](probes/review_2026_09_22.py) assert the **bad behavior**:
a passing probe reproduces the defect; it does not certify correctness. All
database/application state is temporary, transports are fake, and media probes
use tiny local fixtures. Each fix should turn the relevant observation into a
regression test for the corrected behavior.

### C01 — P1: The general budget API can raise a server-managed run cap

`POST /api/budgets` protects `authority:` IDs but accepts `run_guardrail:` IDs.
The same budget can be topped up without changing the run's frozen spending
policy. The probe raises a new run's USD ceiling from 50,000,000 to 100,000,000
microdollars; its displayed policy still says 50,000,000, reports negative
committed spending, and its coverage check accepts 60,000,000 when the separate
aggregate budget permits it. This requires an authenticated mutation, but that
mutation defeats the advertised run cap and leaves the policy internally
inconsistent. Protect internal run budgets at this API boundary and enforce the
frozen cap in the ledger/dispatch path.

Evidence: [API guard](../../modules/factory/api/app.py#L271),
[budget mutation](../../modules/factory/budget/service.py#L69),
`test_general_budget_api_can_raise_fixed_run_guardrail`.

### C02 — P1: Source frames are interpreted using the output frame rate

Blueprint construction stores source intervals in the source's frame clock,
but script adaptation divides those indices by the output clock. A 10-second
24fps source becomes an 8-second source interval for a 30fps output, leaving a
9–10-second passage unassigned. The new source-timing policy does not repair
this when transcript timestamps are already valid. Preserve/use the source
clock or authoritative time intervals, and stop on unexpected lost passages.

Evidence: [source intervals](../../modules/factory/analysis/service.py#L153),
[conversion](../../modules/factory/autorun/service.py#L1299),
`test_source_clock_error_survives_new_timing_policy`.

### C03 — P1: Audio QC compares source mixes without verifying exported audio

Changed-region QC uses supplied mix WAVs instead of the final MP4 audio tracks.
Two real fixture exports with the same picture but different 440Hz/880Hz audio
pass this check when supplied the same mix. Technical checks verify audio
presence/source provenance, not final-to-mix content agreement. New temporal
QC does not close this gap. Keep deterministic mix comparison and add
codec-tolerant verification of exported content and alignment.

Evidence: [mix substitution](../../modules/factory/quality/service.py#L147),
[render-worker inputs](../../modules/factory/services/worker.py#L624),
[technical audio checks](../../modules/factory/quality/technical.py#L62),
`test_wrong_final_audio_passes_mix_comparison`.

### C04 — P2: Auxiliary-route qualification can outlive its expiry

Qualification dates are checked when configured adapters are constructed;
adapters retain a Boolean qualification flag. A running ElevenLabs adapter
still reports qualified and reaches its fake transport after expiry, while
reconstructing it at the same time correctly disables the route. Autorun
readiness only requires authentication for this path. Preserve dated scope on
the adapter and revalidate it before each new effect. The narrow Flashcut/Jev
acceptance guard already rechecks its scoped expiry and is not the reproduced
path here. Drive and other auxiliary constructors also deserve the same audit.

Evidence: [construction gate](../../modules/factory/providers/configured.py#L137),
[cached flag](../../modules/factory/providers/configured.py#L246),
[readiness](../../modules/factory/autorun/readiness.py#L28),
`test_auxiliary_route_qualification_expiry_is_only_checked_at_startup`.

### C05 — P2: Extending run expiry keeps the expired effect authorization

Resume updates `valid_until`, but `_run_effect` reuses its cached authorization
whenever the plan binding matches. It does not check that authorization's
expiry. The queue rejects it again; already-recorded terminal jobs can also
survive because expiry is not a supported reset reason. Renew only safely
undispatched/reconciled scope, revalidate prices, and preserve attempt identity.

Evidence: [cached authorization](../../modules/factory/autorun/service.py#L938),
[reset reasons](../../modules/factory/autorun/service.py#L526),
`test_expiry_renewal_keeps_cached_expired_authorization`.

### C06 — P2: Translation pauses offer unsupported recovery actions

The stage suggests changing `language`, but Resume rejects that parameter.
Incomplete translation suggests retrying, but reset handling does not recognize
that pause or clear the `translate` jobs/plan; Resume consumes the same invalid
result. Implement an audited language change and bounded, reconciled retry, or
replace the instructions with a supported recovery path.

Evidence: [allowed updates](../../modules/factory/autorun/service.py#L381),
[reset tags](../../modules/factory/autorun/service.py#L530),
[translation stage](../../modules/factory/autorun/service.py#L1340),
`test_language_recovery_action_is_rejected`,
`test_translation_reset_keeps_completed_invalid_translation_job`.

### C07 — P2: Autorun discards the selected analysis proxy

Creation accepts but does not persist `analysis_asset_id`; Resume does not allow
it either. The analysis stage looks for exactly that parameter. A registered
proxy therefore cannot be selected through the public autorun path, which
continues using the master. Validate and retain the derivative selection.
This concerns the standard analysis path, not Flashcut's separate compact-media
request builder.

Evidence: [saved parameters](../../modules/factory/autorun/service.py#L122),
[analysis selection](../../modules/factory/autorun/service.py#L1050),
`test_autorun_create_drops_selected_analysis_proxy`.

### C08 — P2: Human QC acceptance is an unbound run-level flag

Human reviews themselves bind to exact artifacts, but autorun then saves
`qc_human_accepted=True` and skips subsequent visual review when it is set.
Replacing finals within the same experiment revision can skip review of those
new bytes after mandatory checks pass. Revision rebind clears the flag; a
same-revision replacement does not. Bind the shortcut to the exact current
finals and resolve acceptance using those reviews.

Scope: the v2 delivery acceptance gate still requires the authoritative
automated review, so this probe does **not** demonstrate that an unreviewed
replacement can be uploaded through that gate. It demonstrates skipped review
and incorrect autorun completion/recovery state. A human pass also does not
currently supersede a failing authoritative automated review for automatic
delivery; the offered human-resolution path needs a coherent policy end to end.

Evidence: [flag write](../../modules/factory/autorun/service.py#L633),
[early return](../../modules/factory/autorun/service.py#L2668),
[delivery acceptance](../../modules/factory/quality/service.py#L205),
`test_human_acceptance_flag_bypasses_replacement_visual_review`.

### C09 — P2: Editing a revision retains delivery jobs for the old finals

Revision rebind resets production and QC state but retains `delivery_jobs`.
Completion sees a previous successful upload and skips submitting the new
artifact. Receipt verification then pauses with `delivery_unverified`; the
normal failed-delivery retry does not replace that successful old job. Clear or
rebind delivery state by experiment revision and artifact hash.

Evidence: [rebind reset](../../modules/factory/autorun/service.py#L497),
[upload reuse](../../modules/factory/autorun/service.py#L2479),
`test_revision_rebind_keeps_old_delivery_jobs`,
`test_old_delivery_job_prevents_upload_of_new_final`.

### C10 — P2: Failed and unprocessed YouTube uploads are labeled public

The verifier computes a processing-aware Boolean, then falls back to
`privacyStatus` when it is false. Public-visibility uploads with status
`failed`, `rejected`, or `uploaded` consequently return `status=public`, which
manual registration trusts. Preserve processing/failure status and require
completed native verification before recording a public post.

Evidence: [verifier](../../modules/factory/integrations/publisher.py#L184),
[registration](../../modules/factory/publishing/service.py#L421),
`test_failed_or_unprocessed_upload_is_verified_public` (three statuses).

### C11 — P2: Otherwise comparable analytics require identical pull timestamps

Ordinary decisions compare the whole window object, which includes
`observed_at`. Identical horizon, coverage and metric definitions pulled one
second apart change a valid winner into `waiting_for_data`. Separate window
compatibility from provenance/freshness; keep pull times in the evidence hash
and apply explicit freshness bounds instead of requiring equality.

Evidence: [equality check](../../modules/factory/learning/service.py#L293),
[timestamp injection](../../modules/factory/learning/service.py#L886),
`test_distinct_pull_timestamps_block_valid_learning_comparison`.

### C12 — P2: Seed selection ignores per-platform exposure and guardrails

The frozen policy permits per-platform thresholds and guardrails, but the
evaluator only uses the primary-metric override. It reads exposure/guardrails
from the global policy. A saved YouTube requirement of 1,000 exposures and an
average-view guardrail still selects B with 200 views and no qualifying
average-view data. Resolve the complete lane policy before evaluating it.

Evidence: [platform evaluator](../../modules/factory/learning/service.py#L422),
[required policy semantics](../factory-publishing-learning-handover.md#9-decision-policy-and-champion-selection),
`test_frozen_per_platform_exposure_and_guardrails_are_ignored`.

### C13 — P2: Seed selection compares incompatible observation definitions

Unlike the ordinary decision path, `select_seed` does not check compatibility
between arms before evaluating a platform. B can win using a source-calendar
window and different query definition while A/C/D use exact rolling windows.
Validate compatible windows, sources and metric definitions before ranking.
This is a separate path from C11: fixing its excessive timestamp equality must
not leave seed selection without compatibility checks.

Evidence: [seed evidence evaluation](../../modules/factory/learning/service.py#L498),
`test_seed_selection_accepts_mixed_window_definitions`.

### C14 — P2: Platform-scoped winners do not count toward template promotion

`independent_experiments` revalidates each saved decision by calling `decide`
without its platform/account scope, then requires the resulting ID to match.
A valid TikTok-scoped winner consequently contributes zero independent
experiments. Persist/reuse the complete decision scope when checking whether
its evidence is still current.

Evidence: [revalidation](../../modules/factory/learning/service.py#L359),
`test_scoped_winners_never_count_for_template_promotion`.

### C15 — P2: A tie between disqualified variants hides an eligible winner

Seed selection returns inconclusive for tied top aggregate scores before
filtering eligibility. If B and D tie but both fail guardrails, a valid C with
twice A's metric is never considered. Test ties and margins among eligible
contenders, retaining disqualified scores for display only.

Evidence: [early tie return](../../modules/factory/learning/service.py#L635),
`test_disqualified_tie_blocks_eligible_seed_winner`.

### C16 — P2: Manual metrics cannot become usable learning evidence

The import service always writes `horizon=manual` and metric availability
`manual`. Learning requires a named horizon and accepts `ok` or
`verified_manual`; even a high-confidence import with an explicit 48-hour
window leaves selection waiting. There is also no public API route invoking
this import service. Add the review/verification and horizon-binding path;
do not silently trust all manual data.

Evidence: [manual import](../../modules/factory/analytics/service.py#L486),
[learning filters](../../modules/factory/learning/service.py#L881),
`test_manual_metrics_cannot_be_selected_as_horizon_evidence`.

### C17 — P2: Stack scripts miss workers started by the documented launcher

`factory.sh worker` inserts `--root .` before `worker`, but orphan detection
expects `modules.factory.cli worker` contiguously. Without a saved PID file,
down misses that worker and up attempts another one, which the worker lock
rejects. Relative-interpreter launches also escape the absolute-path matcher.
Use verified ownership records across supported launch paths.

Evidence: [launcher](../../scripts/factory.sh#L10),
[start matcher](../../scripts/factory-up.sh#L29),
[stop matcher](../../scripts/factory-down.sh#L29),
`test_stack_matcher_misses_documented_launcher`.

### C18 — P3: The pause interface lacks limit and expiry recovery controls

The creation form correctly says per-plan limits now, but paused runs still
offer a Resume payload containing only the current pause identity and selected
budgets. There are no limit/expiry editors for recovery instructions that
require those updates. Expose the supported audited updates and make clear
which caps cannot be raised. Source-inspected; no new UI test was added.

Evidence: [Resume payload](../../apps/factory-dashboard/src/features/autorun/AutoRunScreen.tsx#L352).

### C19 — P2: Batch publishing includes superseded failed reviews

Batch planning gathers every review bound to the final, including superseded
automated visual reviews. After a failed review is replaced by a passing
recheck, `quality.accept` correctly rejects that collected set because it still
contains the superseded failure. The same final passes with its authoritative
current review set. Use the existing authoritative-review resolver when
assembling per-variant publication checks; retaining historical evidence must
not make the batch path permanently unpublishable.

Evidence: [batch review collection](../../modules/factory/services/publication_work.py#L92),
[existing resolver](../../modules/factory/quality/service.py#L97),
`test_batch_publication_includes_superseded_visual_reviews`.

### C20 — P2: Manual publication registration is not exposed to operators

`PublishingService.register_manual` exists and is exercised by QA, but no
application API, dashboard action, worker command or factory CLI calls it.
Operators therefore cannot use the specified manual-first lane to associate
an existing public post with the exact variant/final through the application.
Expose the service through an authenticated, audited operator flow and retain
its platform/account/identity checks. This is an integration gap distinct from
the verifier's incorrect status handling in C10. Source-inspected.

Evidence: [manual registration](../../modules/factory/publishing/service.py#L392),
[publication API surface](../../modules/factory/api/app.py#L531),
[F31 requirement](../viral-video-factory-implementation-modules.md#f31).

### C21 — P2: Publication dispatch ignores loop expiry and post-count limits

The publication loop gate checks stored status and provider/account lists, but
does not compare `valid_until` to the current time or check `max_posts`.
`propose_next` enforces those fields only when creating another proposal.
An existing active policy can expire, or its series can reach the post limit,
while the publication dispatch gate continues allowing new submissions.
Recheck and reserve the remaining loop allowance at dispatch, including races
between queued slots. Individual publication authorization is still required;
the reproduced defect is bypass of the additional recorded loop restrictions.

Evidence: [dispatch gate](../../modules/factory/services/publication_work.py#L127),
[proposal-only limit checks](../../modules/factory/services/rounds.py#L137),
`test_publication_loop_gate_ignores_expiry_and_exhausted_post_cap` (two cases).
