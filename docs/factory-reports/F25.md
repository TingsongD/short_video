## Design decisions

- **Intent before effect.** `deliver()` persists the `Delivery` record
  (file SHA-256, folder, descriptive name, plan linkage) before any
  remote call — a crash mid-upload leaves a resumable intent, never a
  mystery.
- **Remote truth first.** Before uploading, the service lists the
  authorized folder: an identical remote file (name + MD5) is *reused*
  (verified receipt, zero uploads — a second delivery of the same
  final produced `reused` and `uploads == 1`); a same-name
  different-content file is an explicit `conflict`, never silently
  overwritten and never counted as success.
- **Verification is the only completion.** Parent, name, byte size and
  remote MD5 must all match the local final; `checksum_unavailable` or
  `size_mismatch`/`md5_mismatch` problems leave the delivery
  `uploaded`-but-unverified — never "complete".
- **Lost acks reconcile by content.** `FakeDrive.lose_next_upload()`
  creates the remote file then raises; the service finds it by
  name+MD5 and verifies — exactly one remote file, one upload. After
  a "restart" (fresh service over persisted remote state) the same
  holds.
- **Retry is transfer-only.** `retry()` re-uploads the *identical*
  final — a changed file is `final_changed`, a contract violation.
  Failures never rerender; the local final is always retained.
- **Naming carries the story.** `delivery_name` produces
  `exp1-A-hook-r1-30s.mp4` — subject, variant, treatment, revision,
  duration — while the source file stays put.
- **ACL untouched.** Links are plain `/file/d/<id>/view` references;
  sharing settings are never modified.

## Known limitations

- `GdriveCLI` parses the CLI's human listing (`\s{2,}` columns) — if a
  gdrive version changes format, `list_files` may need updating; the
  stat parser normalizes `Md5Checksum`→`md5_checksum` camel-case keys.
- No resumable-session mechanics beyond gdrive's own: the CLI handles
  the transfer internals; the factory layer persists intent + remote
  identity, which is the reconciliation contract that matters.
- F25-M04 remains a live, human-authorized step per the standing
  delivery workflow; nothing in QA uploads to the real folder.
