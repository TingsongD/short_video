## Design decisions

- **Idempotency is durable, not in-memory.** `api_request` records
  persist `key → sha256(method+path+canonical body) → (status,
  response)`. An identical replay returns the stored response; a
  reused key with a changed payload is `409 idempotency_conflict` —
  no second effect, ever. Survives API restart.
- **Revisions are honest CAS.** Draft records carry a logical `_rev`
  plus a row `version`; `X-Expected-Revision` is checked against
  `_rev`, and the UPDATE guards on `version` — a concurrent edit is
  `stale_revision`, not a silent overwrite. `authorize` binds the
  exact quoted revision; a changed plan can never be run on an old
  approval (`not_authorized`/`stale_revision` → 409).
- **Async is 202 + durable.** `run` persists a `Job` through the real
  scheduler (or a durable `job` record) and returns immediately; job
  truth lives in the store, not a connection.
- **Security is a boundary, not a decorator.** One ASGI middleware:
  Host must be loopback (`localhost`/`127.0.0.1`/`::1`/`testserver`);
  mutations with an `Origin` must be loopback-origin; every mutation
  requires `X-CSRF-Token` matching the local session token (issued by
  `POST /api/session`).
- **Media is artifact-addressed.** `/api/assets/{id}/media` resolves
  registered artifact IDs only — path strings and URLs can't reach
  the filesystem (containment enforced inside `path_for`). Bounded
  single `Range` supported (`206`/`416`), full-file `200`.
- **SSE replays from the durable log.** Ordered `seq` IDs;
  `Last-Event-ID` resumes exactly; disconnects are just closed reads
  — work continues server-side. `follow=1` keeps polling; default is
  a finite reconnect-safe response.
- **Errors sanitize.** `ContractError` → `{error, field, detail}`
  (400/404/409/413); anything else → bare `500 internal`. Provider
  readiness reports granular `installed/authenticated/
  catalog_visible/tested/qualified` — never one green flag, never
  credentials.

## Known limitations

- The local session is a single app-scoped token (correct for a
  loopback single-operator deployment); multi-user sessions would
  need per-client tokens + cookies.
- `POST /api/research/plans` and `…/run` return prepared/accepted
  envelopes — the discovery executor wiring lands with the live
  research path (F10 service exists; route-level persistence is the
  API contract being established here).
- SSE `follow` mode polls on a fixed interval; a WebSocket or
  LISTEN-style push can replace it without changing the contract.
- `PATCH` idempotency keys apply per-request as designed; a draft's
  logical history remains in the record body rather than a separate
  audit table (F08 events already capture mutations).
