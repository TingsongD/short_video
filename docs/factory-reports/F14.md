# F14 — Experiment, control and treatment planning

**Module / owner / source revision / completion date:** F14 · Devin · `feat/factory` post-F13 · 2026-09-17

**Scope implemented:** accepted blueprint + template + product snapshots + original copy → frozen control revision + declared A/B/C/D treatments.

- `modules/factory/experiments/service.py` — `ExperimentService.create` builds the control `ExperimentRevision` (revision 1, draft) plus implicit variant `A`. `packaging` freezes: segments, product snapshot refs (id+revision), presenter, voice, music, `provider_policy`, `template_ref` (id+revision), `target_frames`. `content_hash` covers facts only (status/revision/clock fields excluded).
- `branch(variant_key, factor, regions, apply_edits, …)` deep-copies the control packaging, applies the edit, and runs `check_treatment` *before* persisting — violations raise `treatment_violation` with the full problem list and nothing is stored.
- `modules/factory/experiments/diff.py` — `check_treatment` enforces the one-variable policy: every changed segment field must sit inside a declared end-exclusive `FrameInterval` (`change_outside_region`) and in `allowed_fields` (`undeclared_field`); any packaging-level difference (products, presenter, voice, music, provider_policy, template_ref, target_frames) is `locked_field_changed`. Transitive deps: changing `copy` requires `speech`, `captions`, `picture` in the same region (`dependency_outside_region`) — stale mouth motion is never reusable. `diff_plans` produces the semantic+timing diff for review; `to_interval` normalizes both FrameInterval wire shapes (`{start,end}` dataclass vs `{start_frame,end_frame}` serialized — a real bug caught by tests).
- `review` returns the diff + remaining problems + unique-work segment count. `acceptance_report` gates on: blueprint accepted, every segment `claims` string present in product-snapshot claim texts (`unsupported_claim` — "best seller" copy fails), and all segment effects supported by the renderer manifest (`unsupported_shot`).
- `accept` is hash-gated (`revision_mismatch`) and marks draft variants accepted. `revise_control` writes revision+1 as a new row with `parent_hash`, marks every variant `stale_reason=control_revised` (rebased to the new revision pointer), and `json_set`s `status:'stale'` on `PriceAssessment` rows bound to the old plan hash — post-freeze edits never rewrite the accepted row.
- `modules/factory/domain/records.py` — `VariantPlan` gained `segments`, `dependent_fields`, `content_hash`, `stale_reason`; `PriceAssessment` gained `plan_hash`.
