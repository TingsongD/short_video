Reviewed `feat/factory` at HEAD `0d4e950`, including the existing uncommitted analysis and publishing/learning extension. This is a review, not a repair or live qualification. No paid calls or real posts were made. Existing working changes were preserved.

Scope: mission/build instructions, progress and development logs, historical reviews/repair evidence, factory handovers and acceptance tracker, current analytics/learning/publishing/round services, application wiring and dashboard. The legacy pipeline was covered through its documented outstanding gates and the full existing suite, not a new exhaustive line-by-line audit. Historical R/N findings are not automatically reopened; this list concerns current source and explicitly described reproductions.

P1: repair before relying on the affected automated workflow. P2: functional, usability, or evidence defect.

## Remaining implementation issues

| ID | Priority | Issue and consequence | Source |
| --- | --- | --- | --- |
| Q01 | P1 | **Candidate exposure is not enforced globally.** Selection eligibility checks guardrails but ignores `exposure_ok`; weighted-lift selection can crown a candidate below the frozen minimum. Offline reproduction: minimum 100 views, B has one view and 100% average viewing versus 50% for the other arms → B is champion, although its exposure check is false. | [learning/service.py](../../modules/factory/learning/service.py:548), [improvement](../../modules/factory/learning/service.py:623) |
| Q02 | P1 | **Stale/late lifetime evidence can win an earlier checkpoint.** Snapshot eligibility checks window labels/hours and completeness, but not actual observation age or upstream freshness. Offline reproduction: snapshots labeled 48h with observed age 672 hours, `late=true`, and a 2020 upstream timestamp still select B. Recording lateness is insufficient if selection ignores it. | [learning/service.py](../../modules/factory/learning/service.py:761), [snapshot ranking](../../modules/factory/learning/service.py:789) |
| Q03 | P1 | **The implemented ranking is different from the frozen specification.** The spec requires average ranks for ties, `100 × (4-rank)/3`, a minimum winning margin, and a weighted mean of platform-relative lifts. Code uses value divided by platform maximum, ordinal tie ranks, and relative change in the aggregate score; `min_margin` is validated but never used. This can change the champion even with identical source metrics. | [learning/service.py](../../modules/factory/learning/service.py:560), [spec §9.3](../factory-publishing-learning-handover.md:379) |
| Q04 | P1 | **Complete-day readbacks can never become complete through normal collection.** The request excludes the publication day, but `expected_days` starts on that day. Reproduction: supply every requested date September 11–17; the service additionally expects September 10 and reports `partial`. Also, the window always skips the publication day even when publication is exactly at source midnight, contrary to the spec. | [analytics/service.py](../../modules/factory/analytics/service.py:125), [coverage](../../modules/factory/analytics/service.py:213) |
| Q05 | P1 | **Optional thumbnail reach still blocks Shorts decisions.** Completeness intersects analytics and reach dates and requires virtually all normalized metrics, regardless of the selected policy. Reproduction: valid analytics with 2,400 views and no thumbnail rows becomes `pending/no_rows_yet`. A views-based experiment cannot proceed although its required evidence exists. | [analytics/service.py](../../modules/factory/analytics/service.py:265), [coverage intersection](../../modules/factory/analytics/service.py:436) |
| Q06 | P1 | **Checkpoint jobs complete on failed or pending data and do not retry.** `collect` marks the schedule collected/late regardless of snapshot completeness. The worker returns a wrapper without a status, so its generic success path completes the job even when the snapshot is failed/pending. Neither bounded retry nor automatic decision/selection follows. Complete-day horizons are also absent from the automatic scheduling map. | [checkpoints.py](../../modules/factory/services/checkpoints.py:93), [worker.py](../../modules/factory/services/worker.py:96) |
| Q07 | P1 | **Scheduled posts have no durable path to public-state polling.** Publication execution treats `scheduled` as complete; only uploading/processing/unknown continue collection. No subsequent scheduled observation is created. A remotely published scheduled post can remain locally scheduled forever, preventing checkpoint creation unless an operator reconciles it manually. | [publication_work.py](../../modules/factory/services/publication_work.py:145), [publishing/service.py](../../modules/factory/publishing/service.py:159) |
| Q08 | P1 | **Failed cancellation can be reported as successful.** `cancel_remote` ignores the response body; unless reconciliation says public, it writes cancelled. Reproduction: the adapter returns `success:false` and subsequent status remains scheduled; the service returns `cancelled`. The operator may believe a future post was stopped when it will still publish. | [publishing/service.py](../../modules/factory/publishing/service.py:240) |
| Q09 | P1 | **Next-round seeds do not contain the champion master.** `propose_next` creates a metadata-only Seed with the original external URLs; it does not attach the winning final artifact/hash, composition, accepted analysis, or a new A/B/C/D experiment. Reproduction: immediately after a successful proposal, seed readiness is `analysis_ready=false/no_source_media`. The advertised repeat loop currently ends at a lineage placeholder. | [rounds.py](../../modules/factory/services/rounds.py:169), [seed readiness](../../modules/factory/seeds/registry.py:49) |

Existing per-effect authorization still exists, but the extra series limits and stop control are not implemented. | [rounds.py](../../modules/factory/services/rounds.py:244), [pause](../../modules/factory/services/rounds.py:272), [publication dispatch](../../modules/factory/services/publication_work.py:123) |
| Q11 | P2 | **Mature reevaluation does not invalidate a child's basis automatically.** `mark_basis_superseded` has no production caller. Selection chains are horizon-specific, and a mature selection is labeled confirmed just because its horizon matches, without comparing the earlier winner.
