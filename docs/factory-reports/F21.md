## Design decisions

- **Canonical dedupe is the cost model.** A take's request
  (`prompt`+`settings`+`refs`+`audio`) hashes to one WorkItem; identical
  requests across variants share the node AND the charge. Canonical
  fixture: 24 takes → 6 shared control works + 3 single-variant
  replacements = **9 unique pictures, 9 charges** (270 jimeng_credits),
  never 24.
- **Duration fitting is declared, never silent.** `expand_take` picks
  the smallest covering supported duration (5 s → 8 s with `over_s`),
  splits over-max takes into declared chunks (12 s → 8+4 with
  `split_reason`), and names unrepresentable remainders
  `needs_manual` (11 s → `remainder_3.0s_unsupported`). Nothing
  under-length reaches `submit`.
- **Node kinds map to scheduler phases/capacities.** picture →
  `generate_*` (paid pool), download → `collect`, review → `review`,
  compose → `render`, deliver → `deliver`. Compose/deliver nodes are
  planned in the DAG now and stay queued for F22/F25 handlers.
- **Submit-slot holds release on collection.** The F06 hold protects
  in-flight remote ops; the download node polls/downloads attempts
  through the `Executor` (attempts → `downloaded`) then deletes the
  hold — the five-slot `jimeng_submit` pool drains correctly across a
  9-picture graph.
- **Branch isolation by consumers.** `reject_work` marks the node
  rejected and blocks only downstream nodes whose consumers are all
  affected; shared control works and other variants' review/compose/
  deliver chains stay untouched.
- **Manual coverage passes the same gates.** `replace_manual` requires
  `manual`/`stock` provenance and probe duration ≥ the take's need; it
  feeds the download node directly with the artifact id.

## Known limitations

- `run_next` executes one node per claim — a real worker loop lands
  with F26 process ownership.
- Rejected shared work currently requires re-plan; a `revise_plan`
  path (new revision, reusing accepted nodes by `request_hash`) is the
  natural next step when an experiment revision changes.
- `defer` for compose/deliver relies on no handler claiming those
  phases before F22/F25 — documented in `EXECUTABLE`.
- Per-allocation prices are split evenly across a split take for the
  ledger; provider-specific pricing of partials can refine this later.
