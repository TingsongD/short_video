## Design decisions

- **Progress is replayed, not guessed.** `reduceJobs` folds the
  durable event log into per-job stage/state — ready/queued/
  provider-running/downloaded/review/render/upload/cleanup stay
  distinct, with `elapsedBreakdown` giving real per-stage time.
- **Pause/resume tell the truth.** The screen states it plainly:
  pause stops new dispatch while accepted work runs; resume never
  regenerates — regeneration is a separately scoped repair/revision.
- **Comments bind an exact revision.** `import_comment` requires
  `source_revision` and an open session, producing a `proposed_change`
  with a `diff` (`revise_segment` @ time) and `requires_quote` cost —
  never immediate paid regeneration. `mark_stale` invalidates the
  proposal when the reviewed revision moves.
- **Studio sessions are owned.** They register through F26's
  `ResourceRegistry` (pid+birth+command, ports) so F26 cleanup stops
  them safely without touching anything else.
- **Identity over labels.** Compare and review screens print the
  media sha prefix and revision; a stale review target renders the
  accept button disabled with an explanation, not a silent allow.
- **Operator-first status.** "Waiting for provider", "Upload verified",
  "already uses this name" — while md5s, file IDs and problem lists
  sit behind a details disclosure.

## Known limitations

- `reduceJobs` maps `type = "<job>:<stage>"` — a schema for job event
  naming is assumed; wiring real emitters lands with the F30 worker
  integration.
- `CompareScreen` sync-seek is best-effort (0.1 s tolerance, no
  frame-lock); exact frame-step compare remains the F24 SSIM path.
- The Studio launcher is injectable; real `scripts/hypit.sh` session
  startup is exercised in F29-M03's manual walkthrough.
