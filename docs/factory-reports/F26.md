## Design decisions

- **Identity, not PID.** Every registered resource stores
  `pid + birth + command` (reusing `modules.batch.local.same_process`
  / `process_table`). A live process whose identity doesn't match the
  record is a stranger — reported as `pid_reused` / `foreign_untouched`
  and never signaled.
- **Four-way classification.** `per_job` → stopped on owner cleanup;
  `shared` → retained while other holders are active (holder released
  from the lease record, process untouched — A finishing never kills
  B's runtime); `application` → never stopped, always listed;
  `unrelated` → reported, never killed.
- **Escalate only against the verified process.** TERM first, then
  KILL — but each pass re-snapshots the table and signals only
  processes that *still match identity*. A stubborn survivor makes the
  receipt `blocked`, not "verified".
- **Port conflicts are observations.** A recorded port now held by an
  unowned listener is reported in `port_conflicts` (state `blocked`)
  — cleanup never kills an unrelated process to satisfy a port-free
  check.
- **Crash recovery.** `reap_stale` sweeps identity-verified owned
  survivors after restart; reused PIDs are listed as foreign.
  Upload-failure cleanup stops idle render processes while the local
  final and resumable delivery state stay on disk.
- **Completion is conjunctive.** `complete()` requires QC + verified
  delivery + a verified cleanup receipt — an accessible Drive link
  alone is not completion. Receipts persist as `cleanup_receipt`
  events with before/after observations.
- **No RAM claims.** The receipt records memory/port observations; it
  does not claim system memory was freed and never purges unrelated
  caches.

## Known limitations

- `scan_listeners` shells `lsof` (macOS/Linux); on platforms without
  it, `port_fn` is injectable — tests use `FakeOS` throughout.
- The kill escalation uses fixed TERM→sleep→KILL→sleep cadence
  (sleep injectable); stubborn-process reporting is terminal truth,
  not an infinite retry loop.
- Cleanup receipt covers registered resources; unregistered orphans
  are found only via workspace/command heuristics (legacy `Local.
  capture` pattern) — a follow-up could tag every spawn at creation.
