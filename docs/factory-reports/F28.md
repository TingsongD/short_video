## Design decisions

- **States are a contract.** `remoteOf` produces
  loading/empty/ready/error/blocked; tests pin each. Missing metrics
  render "Outlier evidence pending" — never `×0`; `null` ceilings
  render "not set".
- **Revision-bound approval is visible.** The Approve button names
  the revision (`Approved r2`); `Run` sends exactly that revision; a
  `stale_revision` 409 renders "plan changed — re-quote" instead of
  a crash, and Run stays disabled.
- **Idempotent by construction.** Every mutation carries an
  `Idempotency-Key`; the busy-guard swallows double-clicks (one fetch
  verified by test). CSRF token comes from `POST /api/session`.
- **Operator language, not CLI output.** Provider screens say
  "Reconnect Google" / "Set Google budget to enable Vertex"; technical
  detail is reserved for a details panel (none of the screens surface
  tokens or raw provider errors).
- **Fake transports in tests.** No backend needed — `fakeFetch`
  replays the exact F27 wire shapes; the client test asserts the
  endpoint map, headers and error contract.

## Known limitations

- `App.tsx` feeds static demo data (`seeds`, `products`, `blueprint`,
  `budgets` are empty fixtures) — live data wiring lands with F29's
  monitoring screens; providers are the one live fetch.
- Keyboard/at-narrow-width audit is manual (F28-M04); no automated
  a11y linter is wired yet.
- `importFile` uses raw `fetch` for binary bodies; progress callbacks
  for large uploads are out of scope.
