# Hypit upstream review: setup, providers, costs, and adoption constraints

## Scope and conclusion

Source inspection of **Hypit 0.1.8**, pinned to commit [`07bf1cca6730091691030bbe8a064275b2dcf817`](https://github.com/hypit-ai/hypit/tree/07bf1cca6730091691030bbe8a064275b2dcf817). This review read the official repository and license. It did **not** install Hypit, run its tests or render a video, authenticate to HypiHub, or call a generation service. Version comes from the [package manifest](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/package.json#L1-L10), not a claim that a published package was installed or verified.

**Recommendation:** evaluate Hypit as an optional local composition/rendering backend using our existing media and narration. Keep Jimeng generation, credit approval, and publishing gates in our Python workflow. This is an adoption recommendation based on the evidence below; production suitability on this Mac still needs a local rendering pilot.

## Provider defaults and spending

- **The starter profile includes hosted services.** Its endpoints are `hypihub.default`, `media.local`, and `hyperframes.local`; HypiHub uses its own OAuth credential reference. HypiHub serves paid image/video/speech generation and hosted WhisperX. Existing Jimeng authentication does not configure this account. [Starter source](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/video-cli/src/distribution.ts#L26-L47), [HypiHub provider](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hypihub/README.md#L1-L5)
- **Create an explicit local profile for the first pilot.** Select local media, local HyperFrames, and local WhisperX only if alignment is needed. Hypit supports project-written providers, but sharing a model name does not imply a shared API, account, or parameter set. [Provider extension boundary](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/docs/guide/providers.md#L6-L27)
- **Local rendering declares no provider charge.** It still uses our machine's compute and storage. The renderer defaults to one concurrent render request; HypiHub defaults to four concurrent requests when no override is configured. [Local provider declaration](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hyperframes-local/src/provider.ts#L37-L44), [HypiHub defaults](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hypihub/src/provider.ts#L571-L588)
- **Pricing is information, not a hard spending ceiling.** `hypit pricing` groups requests with provider rates and explicitly does not calculate a guaranteed total. HypiHub fetches model pricing documents without calculating a request total. The inspected `build` arguments have no credit-ceiling flag; the build path checks readiness then submits. Do not substitute this for our approved Jimeng credit ceiling and saved submission IDs. [Pricing behavior](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/docs/quickstart/run.md#L278-L298), [pricing implementation](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hypihub/src/provider.ts#L280-L297), [build flags](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/cli/src/arguments.ts#L103-L119), [submission boundary](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/cli/src/main.ts#L403-L425)

No authenticated rate quote or paid-provider price comparison was performed during this review.

## Recovery and artifact handling

Every `hypit build` invocation creates a fresh build ID, even for unchanged inputs. Closing an observer leaves its worker running. Losing the execution context ends that attempt; restarting the worker does **not** resume it. Further execution requires a new build with explicit reuse of completed outputs. Our wrapper must distinguish observing an existing build from creating another one. [Documented recovery semantics](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/docs/quickstart/run.md#L383-L414)

Results default to `.hypit/results`; retrieve an exact `build + output` with `hypit get --output ... --to ...`. Export refuses an existing destination. Supplied local file references remain live, so replacing or deleting a referenced asset changes or breaks later reads. Keep our validated source media stable and record the exact returned build/output before exporting to our production folder. [Result retrieval](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/docs/quickstart/run.md#L416-L443), [file-reference lifetime](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/docs/guide/runtime.md#L136-L159)

## Maturity and validation evidence

The checkout contains **158 TypeScript test files** matching the default runner's glob patterns and **112 package manifests** under `packages/`. These are static file counts, not passing-test counts or coverage percentages. The runner uses Node's built-in tests and a 120-second per-test timeout. [Discovery and runner](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/test/run.mjs#L1-L15), [execution settings](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/test/run.mjs#L44-L73)

Configured CI runs frozen dependency installation, type checking, and tests on **Ubuntu and Windows**, with no macOS leg. Its own comments identify FFmpeg-dependent media tests as skipped when the tool is absent. Real browser rendering is opt-in behind `HYPIT_BROWSER_TESTS=1`, with an additional FFprobe availability check. A green ordinary suite therefore would not establish that our Mac can render the intended production. [CI configuration](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/.github/workflows/ci.yml#L20-L62), [browser test gates](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hyperframes-local/test/provider.test.ts#L19-L20), [real rendering test](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hyperframes-local/test/provider.test.ts#L121-L152)

**Assessment:** the repository has substantial implementation and test structure, but version 0.1.8 and source inspection alone do not justify replacing our verified assembly backend. Pin the version and compare one representative local render against our existing output. The renderer explicitly executes trusted local code rather than sandboxing arbitrary documents/components. [Renderer execution boundary](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/packages/provider-hyperframes-local/README.md#L148-L149)

## License fit for our current use

This is **Apache 2.0 with additional conditions**, not unmodified Apache 2.0. Its text expressly permits running on our own infrastructure for our organization's commercial work, including client work and one-organization deployments. That describes the proposed internal video-production use. [Permitted use](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/LICENSE#L3-L13)

The additional terms restrict third-party hosted/managed/SaaS offerings, multiple outside parties' workspaces, and commercial redistribution of Hypit or derivatives without the producer's authorization/license. They also restrict removing Hypit branding/copyright from surfaced CLI, reports, manifests, and derived user-facing surfaces. Reassess before turning this workflow into a hosted customer product or redistributing its implementation. [Conditions](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/LICENSE#L7-L15)

The producer claims no rights in generated content and permits commercial use of outputs; third-party provider terms remain separate. This is a summary of the inspected terms, not a broader conclusion about every possible deployment. [Output ownership](https://github.com/hypit-ai/hypit/blob/07bf1cca6730091691030bbe8a064275b2dcf817/LICENSE#L22-L24)

## Pilot acceptance checks

1. Pin the executable, prepare only required local endpoints, and record actual versions and setup time.
2. Confirm the planned endpoint list contains no hosted generation or hosted alignment calls.
3. Render one representative portrait video from existing footage and narration; inspect captions, exact shot order, duration, dimensions, audio, and resource use through our existing QC.
4. Close/reconnect the observer once, retrieve the same build's exact output, and verify no duplicate build was created.
5. Keep the existing assembly backend available until the comparison passes; keep generation and publishing approval outside this pilot.

These checks are proposed follow-up work, not completed validation.
